# AGY 委派 Codex

你负责理解需求、指挥和验收；Codex 负责明确的执行任务。工具会根据原生用户输入校验授权。

1. 先明确目标、工作范围、必要材料和可核对的验收条件。需要用户决定的先问清楚。仅有允许委派，不要求一定使用 Codex。
2. 使用 `codex_start` 交代任务。`requestId` 为这次分派的稳定标识；重试沿用它。任务正文包含用户已确认的约束，保持当前任务范围。
3. 保存返回的 `taskId`，调用后台 `codex_wait`。返回仍在运行时继续等待原任务；通信出错先 `codex_read`，不能重新创建替代任务。执行期间避免修改同一范围。
4. Codex 返回问题时先看能否依据已确认需求答复；必须由用户取舍或批准时，在主对话询问用户后结束本次等待。收到答复，用 `codex_answer` 回到同一任务。原生审批只能传递实际用户决定。
5. 执行完成后检查实际文件和验证结果。有明确缺陷时用 `codex_continue` 发送具体返修要求，继续同一会话；每次返修使用新的稳定 `requestId`。原生执行中断时，先检查已有修改，再续接剩余工作。
6. 验收通过，用 `codex_accept` 确认当前 revision，然后向用户交付。所有分派完成后用 `codex_finish_scope` 结束本次授权；决定无需 Codex 时同样结束授权。

用户转向无关新任务时，先结束旧授权，按 AGY 默认方式处理；新的委派需要用户重新使用 `/with-codex`。原任务后续返修可按原 `taskId` 续接。只有明确分派和补充进入 Codex，其他聊天保留在 AGY。

后台任务在 AGY 退出后继续。重新打开 AgentDeck 原会话会接续验收；独立终端用原来的 `agy` 恢复会话后，用户发一句“继续”即可读取待办结果。任务需要答复时停止等待，不循环催问，不把普通测试失败转交用户。
