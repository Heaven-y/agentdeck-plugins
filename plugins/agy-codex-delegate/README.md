# Codex 委派

AgentDeck 的可选工作台插件，让 AGY 在用户明确允许后委派 Codex 执行，随后检查结果并按需返修。

## 使用

安装构建目录并启用插件，打开「Codex 委派」点击「连接并允许委派」。它安装同名 AGY 原生插件，并添加仅允许该插件工具的原生权限规则；已有拒绝或询问规则保留。工作台与独立终端共用任务和设置，无需手动编辑配置。

在 AGY 中发送：

```text
/with-codex 修复这个问题并检查结果
```

AGY 先澄清需求，决定是否委派。授权覆盖本次任务及后续返修；新的任务重新使用命令。也可从输入框的扩展操作插入命令，草稿仍由用户发送。

设置位于工作台的「Codex 委派」。模型、强度、执行范围和审批只配置一次，未选择的项沿用原生配置。服务商、凭据和子代理设置由 Codex 原生配置管理。

插件不占用侧栏顶部导航。通过设置中的「Codex 委派」或对话输入框的「扩展操作 → 查看 Codex 委派」打开同一页面，查看执行设置与任务。

## 任务与接续

- 同目录委派依次执行，返修回到原 Codex 会话。
- 需要外部答复时，问题返回 AGY 主对话；原生权限请求由用户决定。
- AGY 一轮回复结束后，后台工具返回会继续验收。关闭 AGY 后，Codex 继续执行。
- 重新打开 AgentDeck 原会话会接续待办结果；独立终端用 `agy` 恢复会话后发一句“继续”即可。
- 停用插件阻止新委派，已有执行继续。删除 AGY 会话先清理它创建的委派；项目文件保留。
- 更新插件前需结束正在执行或等待原生答复的任务；更新后重启独立执行端。卸载时移除本插件添加的允许规则，原先已有的规则保留。

运行状态和配置保存在插件数据目录，详细执行记录留在 Codex 原生会话。执行端重启后先核对原生状态，状态不明的任务需沿原会话继续，不从头重放。

## 开发

需要 Node.js 22+、本机已配置的 `agy` 和 `codex`。从仓库根目录运行该 workspace 的 `build`、`typecheck`；关联测试位于本插件 tests 目录。宿主需要支持 `session-control` 和 `sessionLifecycle` 接口。

原生接入基线为 AGY 1.5.14、Codex 0.170.0；Hook、后台回传和模型执行的实际验证范围见主仓库委派专题。
